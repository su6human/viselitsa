# Виселица на двоих

Онлайн-игра для двух игроков. У каждого своё слово и своя виселица. Побеждает тот, кто первым отгадал слово. Кого первым повесили (седьмая ошибка), тот проиграл.

Сервер на Node.js, **внешних пакетов нет**: `npm install` не нужен. Слова и проверка букв хранятся на сервере, поэтому подсмотреть слово соперника через браузер нельзя.

## Что внутри

```
server.js       сервер: комнаты, правила игры, раздача сайта
websocket.js    встроенная реализация WebSocket (без пакетов)
public/         сайт: index.html, style.css, app.js
test/           автотесты (node --test, нужен Node 22+)
```

## Запуск у себя

Нужен Node.js 18 или новее.

```
node server.js
```

Откройте http://localhost:3000. Чтобы проверить игру одному, откройте сайт в двух вкладках: каждая вкладка считается отдельным игроком.

Порт задаётся переменной `PORT` (по умолчанию 3000).

## Выложить в интернет

Сайту нужен хостинг, где работает **Node.js и WebSocket**. Обычный хостинг для PHP, GitHub Pages, Netlify и Vercel (как статический сайт) не подойдут: у игры есть серверная часть.

### Вариант 1. Render.com (есть бесплатный тариф)

1. Загрузите папку проекта в репозиторий на GitHub.
2. На render.com нажмите **New → Web Service** и выберите репозиторий.
3. Настройки: Runtime **Node**, Build Command `echo ok` (или оставьте пустым), Start Command `node server.js`.
4. Нажмите **Create Web Service**. Через пару минут сайт будет доступен по адресу вида `https://название.onrender.com`.

Бесплатный сервис «засыпает» после 15 минут без посетителей, и первый заход после этого занимает около минуты. Если сервер перезапустится, текущие партии сбросятся: комнаты хранятся в памяти.

### Вариант 2. Railway или Fly.io

Подходят так же: подключите репозиторий, команда запуска `node server.js`. Порт они передают сами через `PORT`.

### Вариант 3. Свой сервер (VPS)

```
# на сервере с Node.js
git clone <ваш-репозиторий> vesilitsa && cd vesilitsa
npm install -g pm2
PORT=3000 pm2 start server.js --name vesilitsa
pm2 save && pm2 startup
```

Чтобы сайт открывался по домену и с https, поставьте перед ним nginx. В настройках обязательно нужны строки для WebSocket:

```
server {
    server_name example.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 120s;
    }
}
```

Сертификат: `certbot --nginx -d example.com`. Сайт сам выберет `wss://`, если открыт по https.

## Как играть

1. Первый игрок вводит имя и нажимает «Создать комнату», получает четыре цифры.
2. Второй открывает сайт и вводит код. Либо первый нажимает «Скопировать ссылку» и отправляет ссылку вида `https://ваш-сайт/?room=4827`: код подставится сам.
3. Каждый загадывает слово сопернику (или берёт случайное) и отгадывает слово соперника по буквам.
4. После партии можно сыграть реванш.

## Технические заметки

- Игра рассчитана на один процесс: комнаты хранятся в памяти. Не запускайте несколько копий за балансировщиком.
- При обрыве связи место в комнате держится 60 секунд, страницу можно обновить и вернуться в игру.
- Комнаты без активности удаляются через 3 часа. Проверка работоспособности: `/healthz`.
- Проверка: `node --test` (нужен Node 22+ из-за встроенного WebSocket-клиента).
